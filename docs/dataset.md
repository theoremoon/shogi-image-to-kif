# データセットと評価

`data/samples/raw/`にWikimedia Commons由来の原画像12枚を保存。`manifest.json`に説明ページ、原画像URL、作者とクレジットのHTML原文、ライセンス名とURL、取得日、SHA-256、サイズ、種類を記録した。原画像は加工しない。

初期検索結果に混じったレーティングのグラフ（commons-006）はnon-board、駒の動き説明の切り抜き（009/010）はpartial-diagramに分類し、盤の検出失敗を確認する拒否例にした。011は本将棋にない駒を含むvariant-board、012は数値を駒の代わりに置いた説明図。すべてを通常の局面画像として扱わない。

## ラベルとテンプレート

盤面6枚を人手で原画像と照合したSFENとして `data/annotations/<id>.json` に記録。手番は判別できないため `turn_source: manual` とし、テスト用に明示した値である。持ち駒の有無は図の表示と駒配置を確認した。

| ID | 内容 | 用途 |
| --- | --- | --- |
| commons-001 | 嬉野流、先手持ち駒に銀・歩二、黄色のマーク | テンプレート参照 |
| commons-005 | 美濃囲い、別の太字の駒 | テンプレート参照 |
| commons-002 | 嬉野流対策、中盤、黄色のマーク | 動作評価 |
| commons-003 | 相振り飛車、中盤、黄色のマーク | 動作評価 |
| commons-007 | 飛香落ち | 動作評価 |
| commons-008 | 飛車落ち | 動作評価 |

参照2枚から生成した字形は `assets/templates.npz` に含め、出典は `templates-sources.json` に保存。追加の一文字・二文字の駒は複数の日本語フォントで描画したもの。元のフォントファイルは含めない。再生成は `uv run python scripts/build_templates.py`。macOSのヒラギノ、またはLinuxにインストールされたCJK/IPAフォントを使用する。配布済みテンプレートを使う場合はフォントのインストール不要。

## 測定結果

`uv run python scripts/evaluate.py` で [evaluation.json](evaluation.json) を再生成できる。テンプレート参照2枚は評価集計から分離した。

動作評価4枚について **盤面完全一致4/4、マス一致324/324**。加えてJPEG圧縮/リサイズ/180度反転のテストを行っている。この4枚は参照画像と同系統の作者・字体を含み、独立した学習/評価データの精度ではない。SNS全般への一般化を示す値として扱わない。自動OCRの持ち駒・手番はこの盤面評価に含まない。持ち駒は1枚で銀と歩二を読めることを確認したが、画面では常に手動確認する。

ぴよ将棋WEB版の平手キャプチャ1枚でも、テンプレートでは77/81、金と成駒の補助OCRを含めると81/81のマス一致を確認した。字体の一致スコアが低い38マスは要確認として提示する。これはローカル検証用の1枚で、評価セットの集計には含めない。

公開データ12枚とは別に、`scripts/verify_piyo_browser.py` でぴよ将棋WEB版の画面をローカル検証用に保存する。保存先 `data/local-samples/` はGit対象外で、公開データの評価には混ぜない。Xから投稿画像をスクレイピングする機能は実装していない。ユーザーが保存した画像をアプリへ渡して処理できる。

今後モデルを学習する場合は、作者・アプリ・局面・元投稿をグループとし、同じ局面の反転/圧縮/リサイズが学習と評価へまたがらないよう分割する。最低でもぴよ将棋・将棋ウォーズ・将棋クエスト・lishogiなどの字体、成駒、持ち駒、反転、見切れ、低解像度をそれぞれ含む評価用画像を用意する。

## 将棋ウォーズの画面サンプル

`uv run python scripts/collect_wars_samples.py` で、[公式Q&A](https://shogiwars.heroz.jp/qa?locale=ja&num=29) の通常対局・詰めバト画面2枚を `data/local-samples/` に取得する。説明用の番号が重なった公式画像であり、ユーザーが撮った実戦スクショとは区別する。画像の出典・SHA-256・手動指定の盤領域をローカルのmanifestに記録し、原画像はリポジトリに含めない。取得済みファイルは再利用する。

初期結果は [wars-baseline.json](wars-baseline.json) に保持。そこから木目の色と周期的な盤線による検出、五角形の縁・赤い注釈の除去、ウォーズの字形参照を追加した。

`uv run python scripts/setup_wars.py` で取得・字形モデルのローカル再構築・評価をまとめて実行できる。通常対局の1枚だけを字形の参照に使い、詰めバトの別画像を評価する。正解ラベルは `data/annotations/wars-*.json`。詰めバトの公式説明画像は金が5枚あるため、合法局面の棋譜としては使わず、81マスの読み取りだけを評価する。手番はテスト用に指定した値で、自動認識の結果ではない。

最新結果は [wars-evaluation.json](wars-evaluation.json)。どちらも盤を自動検出できる。参照画像は81/81マス一致、別画像は79/81マス一致。別画像の誤認識は龍・馬で、どちらも要確認として提示する。JPEG圧縮、180度反転したJPEG、幅450pxのJPEGでも別画像は79/81。参照画像のJPEG変形では80/81で、すべてのマスを照合する必要がある。1枚だけの別画像評価であり、変形画像は独立サンプルとして数えない。一般のSNS投稿や全スキンに対する認識率ではない。

ローカルモデルは `data/local-samples/wars-templates.npz`。プロジェクト直下で起動すると自動利用し、別の場所から起動する場合は `SHOGI_WARS_TEMPLATES` に絶対パスを設定する。原画像はGit対象外。公開版には数値字形参照 `assets/wars-templates.npz` と出典情報を同梱し、ローカル再構築モデルまたは `SHOGI_WARS_TEMPLATES` がある場合はそちらを優先する。UIでは `wars-play.png` / `wars-mate.png` を開いて `Read →`。手番と持ち駒は手入力・確認する。見切れ、斜め撮影、他の盤面スキン、未参照の成駒は追加検証が必要。
